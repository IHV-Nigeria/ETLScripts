HOW IT WORKS:
=============

Data Flow:
  1. MongoDB ART Containers
     ↓
  2. convert_doc_to_record() → Transform to PostgreSQL record
     ↓
  3. Batch Collection (up to batch_size records)
     ↓
  4. _upsert_batch() → Call batch_upsert_by_quarter()
     ↓
  5. PostgreSQL Quarter-Based Upsert:
     ├─ (PatientUUID, Quarter) exists?
     │  ├─ NO → INSERT new record (+1 inserted)
     │  └─ YES → touchtime newer?
     │     ├─ YES → UPDATE record (+1 updated)
     │     └─ NO → SKIP record (+1 skipped)
     └─ Return statistics
     ↓
  6. Accumulate batch statistics
     ↓
  7. Log results to file and console
     ↓
  8. Return final statistics

UPSERT LOGIC REFERENCE:
=======================

Composite Key: (PatientUUID, Quarter)

For each record from MongoDB:

1. Query PostgreSQL: SELECT * FROM eac_line_list
   WHERE PatientUUID = ? AND Quarter = ?

2. Record Not Found
   └─ ACTION: INSERT new record
      └─ Statistics: +1 inserted

3. Record Found (same quarter)
   └─ Compare: new.touchtime vs db.touchtime
      ├─ new.touchtime > db.touchtime
      │  └─ ACTION: UPDATE all fields
      │     └─ Statistics: +1 updated
      │
      └─ new.touchtime <= db.touchtime
         └─ ACTION: SKIP (don't modify)
            └─ Statistics: +1 skipped

4. Different Quarter
   └─ ACTION: INSERT as new record
      └─ Statistics: +1 inserted

TROUBLESHOOTING:
================

Issue: "ModuleNotFoundError: No module named 'postgresquarterupsert'"
Fix:   Ensure dao/postgresquarterupsert.py exists
       (It was created as part of the upsert system setup)

Issue: "PostgreSQL connection failed"
Fix:   1. Check dao/config.py credentials
       2. Verify PostgreSQL is running
       3. Try connecting manually with pgAdmin or psql client

Issue: "UNIQUE constraint violation"
Fix:   1. Ensure table has: ALTER TABLE eac_quarterly_data
          ADD UNIQUE(PatientUUID, Quarter);
       2. Remove duplicate entries if any
       3. Field names must match exactly (case-sensitive!)

Issue: "No records inserted (0 inserted, 0 updated, 0 skipped)"
Fix:   1. Check MongoDB connection is working
       2. Verify facility cache loads (should show "Loaded X facilities")
       3. Check cutoff_datetime isn't filtering everything out
       4. Verify PatientUUID and Quarter fields are populated

Issue: Slow Performance
Fix:   1. Create recommended indexes on (PatientUUID, Quarter)
       2. Run: VACUUM ANALYZE eac_quarterly_data;
       3. Increase batch_size to 10000
       4. Check database server resources (CPU, memory, disk I/O)
